The Ordo compiler and the v0 decompiler, compiled to WebAssembly and running in this tab. Nothing is sent anywhere: the parser, binder, planner and reverse compiler are the same Rust that the conformance suite runs. Rows are not executed — that needs Postgres. What you get is the SQL each side plans, and the refusals, by name, when a query is outside what the compiler will lower.

What a green answer here proves, and what it does not. It proves this source text compiled to this SQL through the real pipeline. It does not prove Postgres accepted the SQL or returned the rows you expect — the conformance suite proves that, against a seeded database, and it does not run in a browser. On the reverse side, a decompilation is verified by compiling it forward and showing you both SQL texts; their rows are not compared here, so a translation that returns different rows would look fine on this page and be caught by the served playground's differential run.
