# Audit 2026-10-08: React gaps, JSON fields, delegation increment 2, routines, account removal, packages

Batch of 2026-10-07 to 10-08 audited. 3 defects fixed, 6 findings need a decision, the rest sound.

## Fixed

### 1. A text parameter lost its quotes and a backslash was a 500

**Severity: High.**

- `ordo_host::call_source` (crates/ordo-host/src/lib.rs) carried a text, id, datetime or uri value into the call's source as `"<value>"`.
- It stripped every `"` and left `\` raw.
- `He said "hi"` was stored as `He said hi`.
- `C:\path` failed the lexer and answered `internal` (500).

Fix `cf69d005`, crates/ordo-host/src/lib.rs:

- `text_source_literal` escapes `"`, `\`, newline and tab.
- That is the language's closed escape set.
- The import door already did the same.

Test: `a_text_parameter_keeps_its_quotes_backslashes_newlines_and_tabs` in crates/ordo-host/tests/text_params.rs (open and sealed fields).

A regression looks like:

- A quote, backslash, newline or tab missing or changed between a write and the read after it.

### 2. An op that sets one row and deletes another stayed open to delegated tokens

**Severity: Medium.**

- The ruling closes deletes to workers by default (`ORDO_DELEGABLE_OPS`).
- The host classes an op as `Delete` only when every statement is a `del`.
- A body with a `set` and a `del` is a `Write`, and `delegable::close` skipped it.

Fix `e7274550`:

- `OpSpec::deletes_rows()` (crates/ordo-api/src/spec.rs) reads the compiled mode label too.
- `close` (crates/ordo-host/src/delegable.rs) uses it.
- Docs howto-workers.md and settings.md say so.

Test: `an_op_that_sets_and_deletes_is_closed_to_delegation_like_a_delete` (delegable.rs unit test).

A regression looks like:

- `engine.delegable("archive")` is true for an op whose body holds a `del`, with the setting unset.

### 3. The packages workflow published from any ref on a manual run

**Severity: Low.**

- `.github/workflows/packages.yml` ran on `push` to main and on `workflow_dispatch`.
- A dispatch may start from any branch.
- A branch with a bumped version would publish under the real name.

Fix `52e888e6`, .github/workflows/packages.yml:

- The job runs only when `github.ref` is `refs/heads/main` and the owner is HominemAI.
- No test: it is a workflow condition.
- Forks were already safe. `pull_request` is not a trigger and a fork's token cannot write HominemAI packages.
- The token is the automatic `GITHUB_TOKEN` with `packages: write` and `contents: read`, the minimum.

A regression looks like:

- A Packages run on a non-main ref that reaches the publish step.

## Decision needed

### 4. An imported JSON document skips the size and depth limits

**Severity: Low.**

- The door checks `ORDO_JSON_MAX_BYTES` and `ORDO_JSON_MAX_DEPTH` (crates/ordo-api/src/bind.rs).
- The import door (crates/ordo-exec/src/import.rs, `literal`) only checks that the text parses.
- The write protocol's last gate (`fit_json`, crates/ordo-conformance/src/write.rs) does the same.
- A bundle, or a literal in a routine body, can store a document over the limit.
- Only the deployment owner runs an import.

Recommendation: **Check the limits in `fit_json`**, the one gate every path crosses.

- The limits then move from ordo-api to a crate the write path can see.

### 5. A datetime literal cannot be written

**Severity: Low.**

- `is_held_value` in write.rs has no `DatetimeLit` arm.
- So `{ at: 2026-01-01T00:00:00Z }` is refused with "pass it as a parameter".
- A routine takes only `$now` and `$today`.
- A routine body therefore has no way to write a fixed datetime.
- The run handler already passes `$now` as a string to get round it.
- App callers through the door are unaffected: the door spells a datetime as a string literal.

Recommendation: **Add the `DatetimeLit` arm** to `is_held_value`, `eval_expr` (gate text, SQL `TIMESTAMPTZ '...'`) and `folded_literal`, with a conformance case.

### 6. `ordo_host::attribution()` renders principal ids and nothing in production calls it

**Severity: Low.**

- Its only callers are two assertions in crates/ordo-host/tests/delegation.rs.
- The command log's actor comes from the executor (`write_chained_as`).
- That names member ids, so no user sees principal ids.

Recommendation: **Remove it, or move it into the test**, so a future caller cannot pick it up.

### 7. The trigger workers re-list every tenant every second, and each deploy leaves a listener cursor behind

**Severity: Low.**

- `triggers.drain` and `triggers.clock` (crates/ordo-host/src/workers.rs) call `Tenants::list` once a second.
- They then drain every listener in every tenant's database.
- A deployment with N tenants and L change routines runs about N times L queries a second while idle.
- A listener's key carries the program version.
- Each deploy of a changed program registers a new cursor and the old one stays.
- The old cursor pins the prune floor.
- It shows under `orphaned_listeners` until the deployment owner deregisters it.

Recommendation: **Back off when idle, and deregister the previous version's cursor** once the new one has passed its position.

A regression looks like:

- `$logconsumers` growing by one listener row per deploy.
- A prune floor that never moves.

### 8. A tenant unreachable at boot replays its history when it is reached

**Severity: Low.**

- Boot registers every tenant's cursor at the head (`at_head: true`, runtime.rs).
- The drain registers a tenant it has not seen with `at_head: false`, position 0.
- The reasoning: a tenant first seen after boot was created after boot.
- A tenant whose database was unreachable at boot is also first seen then, with a chain of history.
- The routine runs over all of it.
- The guide (howto-routines.md) promises the past is not replayed.

Recommendation: **Register at the head in the drain too**, unless the tenant's registry row is newer than the boot.

- Or record the boot-time misses and register them at the head when reached.

### 9. The device copy's `revoked` latch outlives the manager it was set on

**Severity: Low.**

- `deviceCopy` (clients/ordo-react/src/device.ts) sets `revoked = true` on the first revoking stop.
- It never clears it.
- `rebind()` follows a replaced manager but leaves the latch.
- After a new sign-in, `reload()` returns at once and the copy stays revoked.
- Another agent is in this file for the poison race. Hand it to them.

Recommendation: **Clear the latch in `rebind()`** when the manager changes, and poison again if the new one is revoked.

A regression looks like:

- A signed-in-again device that never reloads.

## Sound

- Routines run in their own tenant only: each run resolves the run's tenant database, the body may write only the program's entities, `$caller` is refused, and a routine name that shadows an op is refused.
- Guards pass on a clock run and `unguarded` lifts the row bound by design (R-G20); the limits, invariants and `rev` of the write protocol still apply.
- A routine is callable by nobody: its op lives in a registry made for one run, and the catalog and `/interface` list only the program's registered ops and the platform's.
- Paused tenants are skipped at the handler, recorded in `$routineskips`, and `nopause` runs anyway.
- A delegated token meets the token gate on `/op`, `/live`, `/blob`, the catalog, `/interface`, `/metrics`, `/usage`, `/health/deep` and the security surfaces; every `/auth/*` route that acts for a person refuses a delegation (`step_up_claims`), and `/auth/refresh` needs a session claim a delegated token never carries; the import door is a platform write and closed.
- A delegated call cannot exceed its grant: the engine intersects the agent's allowlist with the delegator's live reach, refuses a space mismatch and an expired delegation first, and replay and page cursors are keyed on delegator plus agent.
- JSON at the door: size, depth and NUL checked; sealed json seals the compact text and exports as a document; the text-to-json conversion probes with `pg_input_is_valid` and rechecks under an exclusive lock before the ALTER.
- Account removal: the sweep works the due time out from `deleted_at` and the setting in force at each pass; `now` removes inline; `never` runs no sweep.
- React platform op table (share, revokeShare, shares, shareLink, revokeLink, links) matches the server's specs parameter for parameter, and `withPlatformOps` prefers the interface's own descriptor when it carries one.
- `guestClient` and the SDK's `windowFeed`/`linkFeed` hand a tenant and a renewing token function to an ordinary client; nothing is cached across guests.
- The poison design erases the whole replica on the first revoking stop; the race where that clears rows another synced op holds is being fixed by another agent.
