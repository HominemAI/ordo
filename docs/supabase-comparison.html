# Supabase: the grievance Who Ordo today Verdict What to do
Migration history and drift
1 The history table is trusted over the real schema. A dashboard hotfix drifts from the repo and nothing notices. Reported The shape gate refuses to serve on drift. plan diffs the live schema, never a history. Addressed Keep.
2 Files are named by timestamp. A rebase or a second repo breaks db push, and migration repair edits history by hand. Reported A version is the artifact's content hash. There is no file order to get wrong. Addressed Keep.
3 Supabase cannot adopt a database that already exists. Its migrations expect to have made every table, so a running production database has no clean starting point (a "baseline"). Reported Import through the write path is built. ordo introspect is unbuilt, by ruling 18k. Partial Nothing before first deployment. Import covers moving data in.
Long chains of migrations
4 The schema is spread across hundreds of migration files. No one file says what a table is now. Adam The .ordo program is the current state. There is no chain of files. Addressed Keep.
5 A fresh database, branch or reset replays every migration. It is slow, and breaks when an old file no longer runs. Adam A fresh database is one create from the current program (create_schema). Nothing is replayed. Addressed Keep.
6 Squash is the only cleanup. It has lost storage policies and triggers, and its output is unreadable. Reported Nothing to squash. Addressed Keep.
7 (Ordo's version of the chain.) A tenant many versions behind is diffed straight to the current version. Found Ruled: every artifact and plan is kept, and a lagging tenant replays each step in order. Partial Queued, 27a and 27b.
Rollback
8 No down migrations. Requested since 2022, 48 participants. Reported Rollback serves the old version again. Ruled: each step stores its reverse, and a failed migration never switched. Partial Queued, 27a and 27c.
9 migration down --linked resets production. One user lost their whole database. Reported No command resets a deployment's database. See row 24 for the dev loop. Addressed Keep.
10 Nothing keeps a migration compatible with the version already serving. Reported D3 refuses dropping a field the active version reads. --no-activate stages ahead. Addressed Keep.
11 (Ordo.) Required to optional (B6) breaks rollback. Found The plan says so. Nothing enforces it. Gap Reverse rules per change, plan-evolution-plans.md §3.3. Queued, 27a.
The diff tool
12 The diff misses RLS policies, grants, auth triggers, realtime publications, comments and domains. Sign-up breaks in new environments. Reported ddl_for emits a closed, listed set. Access lives in the artifact, not in SQL. Addressed Keep.
13 security_invoker on views is silently dropped. Reported No SQL views or policies to drop. Addressed Keep.
14 Statements come out in the wrong order. JOIN views are regenerated forever. Reported ddl_for runs fixed passes in a fixed order. Addressed Keep.
15 (The cost of the closed set.) Postgres features outside it cannot be expressed at all. Found No escape hatch. Opportunity Decide whether one is wanted.
Locks, downtime and data
16 ALTER TABLE waits behind one slow read and stalls all traffic. lock_timeout is left to each team. Reported schema_apply sets no lock_timeout. A queued ALTER can block a table for up to 30 seconds. Problem Queued. Board apply-lock-timeout.
17 A plain CREATE INDEX blocks writes. Reported CONCURRENTLY, with validity read back. Addressed Keep.
18 A new constraint is checked over the whole table under a lock. Reported Probes run first. NOT VALID then VALIDATE is increment 3. Partial NOT VALID then validate; uniques via a concurrent index. Board apply-lock-timeout.
19 Data migrations are hand-written. Backfills hold locks, and schema and data cannot be retried apart. Reported Ruled: choices are made in the plan, with a committable receipt. Partial Queued, 27a.
20 How long a migration takes is only known once it runs. Reported plan prints a freeze estimate before anything runs. Addressed Keep.
40 Does the deployment serve every version its tenants are on? Adam One version back (D-B2). You asked what serving more costs. Gap Board evolution-plans, ask 3, put again.
Tables from other systems in the same database
21 The diff guesses ownership. Another system's tables show up as yours or as a DROP. Adam Extra live tables, columns and constraints are not drift, and are never proposed for drop. Addressed Keep.
22 There is no clean way to reference data another system owns. Adam Ruled: external entities, generated read-only projections. Not deferred. Partial Queued, 27i.
23 The other owner's change flags your drift. Unannounced auth indexes broke every Prisma project. Reported Extra live objects are tolerated. Addressed Keep.
24 db reset wipes every table, including other systems'. Reported ordo dev runs DROP SCHEMA public CASCADE on any database it is pointed at. Ruled 2026-10-01: drop only the program's tables and note the rest. Problem Queued. Board dev-reset-foreign.
25 A name another system already uses. Found Ruled: Ordo's tables move under a prefix plus a random identifier. Partial Queued, 27k.
26 Your foreign key on their table breaks their operations (profiles to auth.users). Reported The reverse applies: an outside foreign key into an Ordo table blocks Ordo's deletes and drops. Increment 5 does not look for one. Gap Ruled: the first apply lists untracked tables and errors on a clash. Queued, 27j.
27 (Ordo.) Another system writes straight into an Ordo table. Found Ruled 2026-10-01: direct database access is discouraged and handled by access control. Ordo's role alone writes its tables. Grants not yet audited. Partial Audit, board deploy-schema-audit.
28 must be owner of table when the migrating role differs from the one that created the table. Reported Roles are Postgres roles, not people. In Supabase everyone applies as postgres, so two people's migrations share one owner; the clash is with Supabase's own service roles. Ordo's parallel: the deployment's role against a tenant database's owner. Partial Board deploy-schema-audit.
29 The API's schema cache goes stale, or reloads on every DDL. One project lost 371 seconds in 28 hours. Reported Ordo serves from the artifact, not from a schema cache read off the database. Addressed Keep.
41 An app sharing the database cannot use Ordo's data, because direct database access is discouraged. Adam Ruled: other systems reach Ordo through the door. Grant-based views maybe, later. Addressed Keep. Views: 27u, not planned.
Platform-owned schemas and access
30 auth, storage and realtime were locked in April 2025. Old migrations now fail. Reported Std entities live in the program. A clash between std and user names is unverified. Partial Audit first (deploy-schema-audit), then random schema names.
31 Making a table reachable takes a dashboard setting plus grants. The default flips on 30 Oct 2026. Reported Nothing is reachable unless an op exposes it, and ops are in the artifact. Addressed Keep.
32 Generated types are a manual step, lag the schema, and change between runs. Reported Types come from the same compiled program as the DDL. Addressed Keep.
Dev, staging and production
33 Local behaves differently from hosted: Postgres version, realtime, RLS, OAuth. Reported Ruled: dev by default, then staging, then production, each gated on the one before. Partial Queued, 27e and 27f.
34 Staging is a separate project kept in step by hand. Reported Ruled: promotion by hash, once compiling is proven byte-stable. Partial Queued, 27e and 27f.
35 Branches cost about a project each. A merge deleted a client's UAT database. Reported Ruled: a dev branch is a tenant in the dev deployment. Promoting one for special tenants comes later. Partial Queued, 27g. Future: tenant-builds.
36 Auth settings and secrets do not travel with the schema. Reported Environment variables read by server and dev alike. A bad value refuses to start. Still set by hand in each environment. Partial Board settings-in-code (18ac).
37 No safe way to get realistic data. Seeding auth.users is awkward. Reported Ruled: staging clones mask personal data by default, as the app developer's setting. Gap Queued, 27v. Future: data-generation.
38 Destructive commands look the same in every environment. Reported ordo rollback and future drops do not know which environment they aim at. Gap With the rollout build (27h).
39 A preview branch replays history and fails as MIGRATIONS_FAILED. Reported Ruled: migration is seamless. The old version serves until the new one works, so a failure shuts nobody out. Partial Queued, 27c.
