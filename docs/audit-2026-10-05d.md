## Fixed

### 1. Deleting an account left its delegations and recovery approvals behind

**Medium.** Fixed in commit a406073.

- `identity_removal::remove` deleted five personal tables by a `principal`
  column, and skipped any table without one, in silence.
- `$delegation` names a person as `delegator` or `agent`; `$recoveryapproval`
  as `approver`. Neither has `principal`, so both were skipped.
- After `POST /auth/account/delete` the person's delegations, given and held,
  and their approvals were still there, naming them.
- Now each table lists the columns that name a person, and a listed column
  the table lacks is an error, not a skip.
- The same commit routes the one remaining identity removal outside
  `identity_removal::remove` (a never-signed-in managed identity on a leave,
  `release_ops::settle_identity`) through it, so R6's "one path" holds.

Test: `deleting_an_account_removes_its_delegations_and_recovery_approvals`
(`crates/ordo-host/tests/member_release.rs`).

A regression looks like: a `$delegation` row with the deleted id in
`delegator` or `agent`, or a `$recoveryapproval` row with it in `approver`,
surviving the route's 200.

## Decision needed

### 2. The leave's command group keeps the person's display name in the chain

**Medium.** Decision needed; nothing built.

- The leave is one command group, imaged before and after (8c97b7e). The
  seat's before-image is the whole `members` row: `principal` and
  `displayName` as they were.
- Ask 10 ruled that a random id with nothing behind it is the erasure
  promised. The image carries more than the id: the name the person went by.
- Every converge of a `members` row already does this (`setRole`, `suspend`,
  through the membership surface), so the leave did not start it. The leave
  is the first write made in the person's own name on their way out.
- The chain is never rewritten, so no later act removes it.

Recommendation: **rule it, as a new ask on `person-can-leave`.** Either the
display name is tenant data the chain may keep, which `plan-member-release.md`
§5.4 should then say plainly, or `members.displayName` becomes a field whose
images are sealed or omitted. The second is a protocol change and needs a
plan. Until ruled, the guide `howto-leave.md` should not promise that the
name is gone from the record.

### 3. A rescale moves every amount and nothing downstream is told

**Low.** Decision needed; nothing built.

- `--places <entity>.<field>=rescale` multiplies or divides the column in one
  statement, inside the migration's transaction, with no command group and
  no `rev` bump (allow-listed in a685c73).
- A revert past it is already on the board (`revert-past-rescale`, 25ad).
- Anything that keys on `rev` or the chain, such as a sync pull or a device
  copy, sees the rows unchanged and reads the old numbers at the new places.
- The op's version hash moves with the field type, which may drop cached
  answers; the row-level record does not move.

Recommendation: **bump `rev` on every row the rescale moves**, in the same
`UPDATE`. It costs nothing, keeps the tripwire's "no group" reasoning, and
makes sync re-send the rows. Whether the chain should carry the rescale is
25ad's question, not this one.

### 4. Trigger runs will not ask the pause register when a runner exists

**Low.** A hazard for 12a, not a defect today.

- The binary registers no `RunHandler`, so `triggers.runner` is disabled and
  `triggers.clock` only writes `$triggerruns` rows nobody claims. Nothing runs
  in a paused tenant today, as `howto-pause.md` says.
- When a routine executor lands, the runner and the clock walk tenants
  without reading `Spaces::paused_record`, and listener runs claimed before a
  pause would execute during it.

Recommendation: **gate at the handler seam** (`supervisor::RunHandler`),
default skip and record, as ask 5 ruled. Put it on the 12a task so it is not
rediscovered.

## Notes, no fix

5. **The blob door refuses a `nopause` op's files.** `blob.rs` checks the
   register with no op in hand, so a paused tenant cannot upload or read a
   file for an op the app marked `nopause`. `howto-pause.md` says so.
   Acceptable until an app needs it. Low.

6. **One unreadable store name stops the whole sweep.** `blobgc` resolves
   each tombstone's recorded store; a name whose credential label is no
   longer installed is `Config`, and the pass stops, deletions in other stores
   included. Skipping that name and continuing would be kinder. Low.

7. **Share tickets the person issued stay.** `remove_identity` deletes
   unredeemed tickets by `principal`; tickets with the person in `issued_by`
   remain. They cannot be accepted (`sharer-gone`), but they name the id. Low.

8. **Account delete reads memberships from the door's engine.** A seat
   admitted on another replica inside the refresh interval is not seen, and
   the account deletes with a seat pointing at a gone principal. Bounded by
   `ORDO_ACCESS_REFRESH_SECS`. Low.

9. **A revert of a leave is `ordo revert` at the database.** It restores the
   seat; the door learns of it on the next access refresh, as for any revert
   that touches `members`. The grants revoked and a managed identity released
   after the commit are not restored, as `release_ops.rs` says. Low.

10. **The multiply has no in-transaction guard.** The divide re-checks lost
    digits under the table lock; the multiply trusts the plan's probe. A row
    written since the plan past `i64::MAX / factor` fails the statement with a
    database error, so it fails closed, with worse words. Low.

## Looked at and found sound

- **Who may pause.** `pauseTenant` and `resumeTenant` are owner-only and
  answer only in the deployment's own space (`in_home`); the home space
  cannot be paused. `std.space.pause` and `resume` go to nobody until
  `ORDO_TENANT_PAUSE_ROLES` names roles. All four need a fresh passkey by
  default.
- **The registry transitions.** `active` to `paused` and back are single
  guarded statements; a resume from inside lifts only a tenant's own pause.
- **Replicas.** The replica that pauses holds at once, announces on
  `ordo.members`, every other reloads the whole register, and
  `tenants.pause.refresh` is the ceiling; the register is loaded at boot.
- **The gate's reach.** It sits in `PlatformExecutor::execute`, after the
  access check, and every op path (the router, sync, refine) goes through the
  one executor. The blob door checks the register on write and read. A share
  accept and an invitation arrival check the registry before spending the
  ticket. Leave, import, share, invite, admit, attach, detach and attestTo
  are refused; the member commands that narrow access, export, delete and the
  read-backs answer. A caller with no membership is told `access_denied`.
- **423.** `space_paused` is never cached by replay and is marked as one the
  executor may raise.
- **The store name.** Only the pipeline writes it, from the route it
  resolved in the same call; import re-uploads through the pipeline and
  copies no `$blobref` row, so a tenant cannot steer it. It holds endpoint,
  region, bucket, the credential **label**, custody, path style and prefix,
  never key material, and the export bundle does not carry it. A name that
  does not parse is `Config`, never "that file is gone". Reads, the sweep,
  erasure, export and the re-seal pass all follow it; the re-seal writes the
  new object where the space writes now.
- **422.** `sealed_unsupported` answers 422, the React runtime reads it as
  the request's fault, and the refine sweep no longer admits a 501.
- **The leave.** One SERIALIZABLE transaction: the seat locked, the
  platform's conditions first, the rule, targets resolved before any effect,
  then the protocol's own release entry. Every write is the protocol's, one
  correlation joins the group, the append is in the transaction, and a
  serialization conflict retries the whole decision. A reassign that names
  two people names nobody; a reassign that names nobody while rows point at
  the seat holds it.
- **Guards skipped for release effects.** Only for the effects the program
  wrote and the seat's own acl rows; structure still holds (tree parents,
  plain referrers, foreign keys and unique keys all come back as
  `release_held`). The seat's actor is attributed, so the group is not rule 6.
- **The former member.** A `left` seat is no membership at the door, keeps
  the rows that point at it, and reads as `former member`.
- **Account delete.** A session token only, fresh presence, the id typed
  back, every tenant listed with its bar including a tenant of their own,
  sessions ended before anything is removed, and the record carries no name.
- **Places.** B11 is found under `same_type`, so a decimal's scale change is
  a places change and not a type change. `$places` outranks the live scale,
  which outranks the version the data was written under. The probe runs at
  plan time; the apply takes an exclusive lock and re-checks lost digits in
  the transaction, and writes the `$places` row in it. The load gate refuses
  a version whose places drift from `$places`, and a tenant's database is
  brought forward with the choices the deployment stated.
- **The tripwire.** a685c73 adds `schema_apply.rs` to the allow-list for the
  rescale, with its reason beside the re-seal pass. This audit adds nothing
  to it.
