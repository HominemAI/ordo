1The recommendation on one screen

Run each function as a fresh WebAssembly instance inside Ordo, and let it reach data only through ops. This is Fastly's runtime model with Convex's data model, plus Ordo's sealed secrets.

Where it runs

Inside the Ordo binary, in wasmtime. A JS engine (StarlingMonkey) is compiled to Wasm, so a function is a plain bundled JS file. No containers, no extra infrastructure.

How fast

A fresh instance per call, made from a snapshot taken at apply. Fastly reports about 5 microseconds to start one. Nothing is shared between calls, so nothing leaks between tenants.

How it reaches data

Only through the program's ops. It runs as the caller, through a grant the program declares, or as its own principal. There is no service key and no database URL.

Secrets

Sealed by custody. The function holds a handle. The egress kernel fills in the value only for the host the secret is bound to.

How it ships

With the program. ordo apply stores the code by hash beside the ops. The SDK can take a function inline and bundle it.

Long-running services

A later, separate track. First an identity and a door for code the app developer runs. Then Ordo starts and stops it. A scheduler comes last.

Why this and not the others

  • V8 isolates port fastest from Cloudflare. They also pull a large C++ engine into the binary. Cloudflare needed process sandboxes, frozen timers and a 24-hour patch pipeline to make them safe.
  • MicroVMs are the strongest wall. They need KVM on the host, a guest kernel per call, and about 125 ms to boot.
  • Containers fit long-running services. For a 2-second model call they cost too much.
  • The edge buys little here. Ellanor's functions spend their time waiting on a model API. Running near the database matters more than running near the person.
  • Cloudflare stays until this is built (ruled 2026-10-08).

2How Supabase and Cloudflare build it

What Ordo takes from each

  • From Supabase: a trusted front (Ordo's door) in front of untrusted code. Ordo drops the service key: no function gets a way around access rules.
  • From Cloudflare: bindings. A function is handed capabilities, never credentials. Ordo goes further: even its secrets are handles.
  • From Cloudflare's security model: layers. A Wasm sandbox first, a separate functions pod with seccomp second, when the deployment owner wants it.

5Ordo's design, drawn

Where it runs

  • By default, in every Ordo process. Nothing to install.
  • Optionally, in its own pod with ORDO_WORKERS=functions. The deployment owner chooses. That pod gets a tighter seccomp profile and no database pool of its own; it calls ops back through the host.
  • Per tenant: every call gets its own instance. The tenant id is fixed in ctx by the host. Ops resolve to that tenant's database. A semaphore caps concurrent calls per tenant (default 10).

How it reaches data

As the caller

A page call. A delegation from the person to function:x@v for this one call. It can never reach past what the person can. Ruled 2026-10-08.

Through a grant

The program declares a grant the function carries, such as a public grant or a narrow write. The owner raised this on 2026-10-08. It is decision 3 below.

As itself

A schedule or change runs as function:x@v, with routine rules. A webhook runs as source:x, write-only.

Never

No service key, no SQL, no database URL. Ops are the only normal way to transact (ruled 2026-10-08), so a function uses them too.

The caching layers

How the SDK passes a function in

The owner: "our sdks will allow the passing in of functions." The CDK takes the function body inline and turns it into the same two things a hand-written program has.

// infra/notes.ts
fn("classifyNotes", {
  in: "notes",
  call: { notes: json() }, returns: json(),
  by: "member",
  egress: ["api.openai.com"],
  secrets: ["openaiKey"],
}, async ({ notes }, ctx) => {
  const r = await fetch(OPENAI, {
    method: "POST",
    headers: {
      authorization: ctx.secret("openaiKey").bearer(),
    },
    body: JSON.stringify(build(notes)),
  });
  return parse(await r.json());
});
  • The closure may not capture anything from the CDK file except imports. Synth refuses it otherwise, because it runs somewhere else.
  • A function in a file (code "fn/x.js") gives the same result. The two are interchangeable.
  • Languages: TS and JS first. Rust and Go compile to Wasm directly. Python through componentize-py. Java is the least mature Wasm path today ?.

6Backend service as a service

A function wakes, answers, and is gone. A service is a program the app developer wants running: an HTTP server, a worker, a queue consumer. The owner asked for both: "backend service as a service allowing users to deploy actual service code to run on ordo and serve."

A phased path

0

Today: code elsewhere, acting through delegation

A worker on Cloudflare or Fly holds a delegation and calls ops. Built. Worker credentials wait for the post-deploy roadmap (ruled 2026-10-08).

1

A declared service: identity and door

A service block names an image by digest, its grant, its hosts and secrets. The CDK writes the cluster manifests. Ordo gives it service:name, a route through the door and the egress proxy. Ordo runs no scheduler.

2

Ordo wakes and sleeps it

The door starts the service on a request and stops it when idle, the way Cloudflare Containers and Fly do. Idle services cost nothing.

3

Queues and schedules for services

A routine's outbox becomes a queue a service consumes, with the same retries and dead letters. Cron wakes a service like a function.

4

Hosted Ordo: other people's code

When one cluster runs many app developers' services, each runs in a microVM runtime (Kata with Firecracker, or gVisor). Until then the app developer owns the cluster and trusts their own code.

7Open decisions for the owner

1 · Do functions run as WebAssembly in Ordo (wasmtime with a JS engine), rather than V8 isolates?
Yes, Wasm. It needs nothing beyond the Ordo binary, starts in microseconds and takes any language later. V8 ports Cloudflare code faster but ties Ordo to JS and a large C++ engine.
2 · Does every call get a fresh instance, with nothing kept between calls?
Yes, fresh per call. A snapshot makes it nearly free, and no state can pass between people or tenants. Cloudflare and Vercel reuse a warm process, where one request's leftovers can reach the next.
3 · May the program give a function its own grant, used instead of the caller's reach?
Yes, declared in the program and recorded on every use. It covers "pass along grants" and public grants without a service key. The grant names its ops, so it can never be wider than written.
4 · Does the SDK take a function inline and bundle it at synth?
Yes, beside code in a file. Both produce the same function block and hashed file. An inline function may capture only imports, so it behaves the same wherever it runs.
5 · May a public function opt in to the public path's result cache?
Yes, opt-in and public only. It reuses the cache and invalidation the public path already has. A signed-in call is never cached, because its answer belongs to one person.
6 · For services, does Ordo start with identity and a door, and leave running containers to the cluster?
Yes, phase 1 first. It gives services Ordo's promises (ops only, sealed secrets) with no scheduler to build. Waking and sleeping comes in phase 2.
